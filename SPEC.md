# API specification

Every implementation in this repository serves this contract. The harness
verifies equivalence before it measures anything: if two servers disagree on a
response, the sample is rejected rather than reported.

The shape is a content API for a tech-news publication with an editorial admin
surface and a scraper ingestion surface. That combination is deliberate. It is
the ordinary FastAPI workload — read-heavy public endpoints, validation-heavy
writes, bulk ingestion from crawlers, file upload, and a live feed — so it
exercises what actually differs between frameworks rather than what is easy to
benchmark.

## Ports

| Implementation | Port |
| --- | ---: |
| Blazingly | 3201 |
| Axum | 3202 |
| Actix Web | 3203 |
| FastAPI | 3205 |

## Storage

All four load `data/seed.json` at startup into an in-memory store. No database.

This is a deliberate limitation. Measuring a database would measure drivers,
connection pools, and query planners, not frameworks. It also removes the one
thing FastAPI users genuinely suffer from in production — a synchronous driver
blocking the event loop — so this suite must not be read as a claim about real
deployments. A second variant with a real database belongs in a separate run.

The store is read-mostly. Write endpoints mutate it, so the harness runs write
scenarios against a freshly started server.

## Seed data

`data/seed.json` is generated by `tools/generate_seed.py` from a fixed seed and
committed, so every implementation loads byte-identical data.

- 1000 articles, ids `1..1000`, slugs `article-0001` … `article-1000`
- 12 categories, ids `1..12`
- 40 tags, ids `1..40`
- 25 authors, ids `1..25`
- 200 companies, ids `1..200`

Articles are pre-sorted by `published_at` descending, then by `id` descending.
That ordering is the default for every listing, so no implementation may rely
on incidental map ordering.

## Authentication

Two schemes, both fixed for reproducibility.

- Editorial: `Authorization: Bearer editor-token` grants role `editor`;
  `Bearer admin-token` grants role `admin`. Any other value is 401.
- Ingestion: `X-API-Key: scraper-key`. Any other value is 401.

Real JWT verification is out of scope: it would measure a crypto library.

## Response conventions

- `Content-Type: application/json` unless stated otherwise.
- Timestamps are RFC 3339 with a `Z` offset, e.g. `2026-03-14T09:00:00Z`.
- Field order in JSON objects follows the order given below. Implementations
  that cannot control field order are still equivalent; the harness compares
  parsed JSON, not bytes.
- Unknown query parameters are ignored.

## Public endpoints

### `GET /articles`

Query parameters:

| Name | Type | Default | Rules |
| --- | --- | --- | --- |
| `page` | integer | 1 | `>= 1`, else 422 |
| `limit` | integer | 20 | `1..=100`, else 422 |
| `category` | string | – | category slug; unknown slug yields an empty page, not 404 |
| `tag` | string | – | tag slug |
| `author` | string | – | author slug |
| `lang` | string | – | one of `uk`, `ru`, `en`, else 422 |
| `q` | string | – | case-insensitive substring match over title and excerpt |

Filters combine with AND. Response:

```json
{
  "items": [ArticleSummary],
  "page": 2,
  "limit": 20,
  "total": 1000,
  "pages": 50
}
```

`ArticleSummary`:

```json
{
  "id": 42,
  "slug": "article-0042",
  "title": "...",
  "excerpt": "...",
  "lang": "uk",
  "published_at": "2026-03-14T09:00:00Z",
  "reading_minutes": 4,
  "views": 15234,
  "category": {"id": 3, "slug": "startups", "name": "Стартапи"},
  "author": {"id": 7, "slug": "author-07", "name": "..."},
  "tags": [{"id": 5, "slug": "ai", "name": "AI"}],
  "cover_url": "https://cdn.example/covers/0042.jpg"
}
```

### `GET /articles/{slug}`

404 with an error body when the slug is unknown. Response is `ArticleDetail`:
every `ArticleSummary` field plus `body` (markdown string), `updated_at`, and
`related` (up to 3 `ArticleSummary` from the same category, excluding itself).

### `GET /categories`, `GET /tags`

Flat arrays of `{"id", "slug", "name", "article_count"}`.

### `GET /authors/{slug}`

`{"id", "slug", "name", "bio", "article_count"}`, 404 when unknown.

### `GET /companies`

Query: `page`, `limit` as above, plus `industry` (string), `stage` (one of
`seed`, `series_a`, `series_b`, `growth`), `min_funding` (integer, USD).
Same envelope as `/articles`. `Company`:

```json
{
  "id": 1, "slug": "company-001", "name": "...", "industry": "fintech",
  "stage": "series_a", "founded_year": 2019, "employees": 85,
  "total_funding_usd": 12000000, "website": "https://example.com"
}
```

### `GET /search?q=`

`q` is required and must be 2..=100 characters, else 422. Searches articles and
companies. Response:

```json
{"query": "ai", "articles": [ArticleSummary], "companies": [Company]}
```

Capped at 10 of each.

## Editorial endpoints

All require the editorial bearer token. 401 without it, 403 when the role is
insufficient.

### `POST /admin/articles` (role `editor`)

Body:

```json
{
  "title": "...", "slug": "...", "excerpt": "...", "body": "...",
  "lang": "uk", "category_id": 3, "author_id": 7, "tag_ids": [5, 9]
}
```

Validation, all failures 422:

- `title`: 8..=200 characters
- `slug`: 3..=200, pattern `^[a-z0-9]+(-[a-z0-9]+)*$`, must not already exist
- `excerpt`: 20..=500
- `body`: at least 50 characters
- `lang`: one of `uk`, `ru`, `en`
- `category_id`, `author_id`: must exist
- `tag_ids`: 0..=10 entries, each must exist, no duplicates

Success is 201 with the created `ArticleDetail` and a `Location` header.

### `PATCH /admin/articles/{id}` (role `editor`)

Every field optional, same rules when present. 404 when the id is unknown.

### `DELETE /admin/articles/{id}` (role `admin`)

204 on success, 404 when unknown, 403 for role `editor`.

### `POST /admin/articles/{id}/cover` (role `editor`)

`multipart/form-data` with one `file` part. Accepts `image/jpeg` and
`image/png`, rejects anything else with 415. Maximum 10 MiB; larger is 413.
The bytes are counted and discarded, not stored. Response:

```json
{"id": 42, "cover_url": "...", "bytes": 5242880, "content_type": "image/jpeg"}
```

This endpoint is the streaming-upload scenario. An implementation that buffers
the whole body before the handler runs is still correct; the harness reports
peak RSS during the upload, which is where the difference shows.

### `POST /admin/articles/{id}/publish` (role `editor`)

Body `{"published_at": "2026-04-01T12:00:00Z"}`. Rejects a timestamp more than
one year in the future with 422. Returns the updated `ArticleDetail`.
Publishing an already-published article is 409.

## Ingestion endpoints

Require `X-API-Key`. Rate limit: 100 requests per second per key, 429 beyond
it, with `Retry-After`.

### `POST /ingest/articles/bulk`

Body `{"items": [CreateArticle]}`, 1..=100 items. Each item is validated
independently and the response reports every outcome rather than failing the
batch:

```json
{
  "accepted": 47,
  "rejected": 3,
  "results": [
    {"index": 0, "status": "created", "id": 1001, "slug": "..."},
    {"index": 1, "status": "rejected", "errors": [{"field": "title", "code": "min_length", "message": "..."}]},
    {"index": 2, "status": "duplicate", "slug": "..."}
  ]
}
```

Status is always 200 when the envelope itself is valid, even if every item was
rejected. A malformed envelope is 422.

This is the validation-heavy scenario. It is where per-item error reporting,
error-path allocation, and validation cost show up.

### `POST /ingest/runs`

Body `{"source": "...", "started_at": "...", "finished_at": "...", "found": 120, "ingested": 47, "errors": 3}`.
`finished_at` must not precede `started_at`, else 422. Returns 201 with the
stored run and a generated `id`.

## Operational endpoints

### `GET /health`

`{"status": "ok", "articles": 1000, "uptime_seconds": 12}`. No auth.

### `GET /events`

Server-Sent Events. Emits one `article` event per second with the newest
article summary as JSON data, plus a comment heartbeat every 5 events. The
harness holds N concurrent subscribers and measures memory per connection.

## Error bodies

Status codes are part of the contract; error body shape is not. Each
implementation uses its framework's idiomatic error format, because that
format — and how much code it costs to produce — is one of the things being
compared. The harness asserts on status codes and on the `results[].errors`
structure of the bulk endpoint only.

## Benchmark scenarios

| Name | Request | What it measures |
| --- | --- | --- |
| `list` | `GET /articles?page=3&limit=20` | listing, pagination, nested serialization |
| `detail` | `GET /articles/article-0042` | single item plus related lookup |
| `filter` | `GET /articles?category=startups&lang=uk&limit=20` | filtering over the full set |
| `search` | `GET /search?q=ai` | substring scan over two collections |
| `bulk` | `POST /ingest/articles/bulk`, 50 items, 10 invalid | validation and per-item error reporting |
| `upload` | `POST /admin/articles/1/cover`, 5 MiB | request-body handling and peak RSS |
| `sse` | `GET /events`, N subscribers | memory per idle streaming connection |

`list`, `detail`, `filter`, and `search` are read-only and run against a warm
server. `bulk` and `upload` mutate, so each sample restarts the server.
